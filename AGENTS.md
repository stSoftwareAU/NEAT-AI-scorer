# AGENTS.md

- Workspace member: **`rust_scorer`** (CLI + `float_scan_bench`). **`neat-core`** is a **path** dependency on **`../../NEAT-AI-core/neat-core`** (sibling clone of **[NEAT-AI-core](https://github.com/stSoftwareAU/NEAT-AI-core)**). Forward-only scoring uses **`neat_core::training_bin_stream::for_each_read_chunk`** only (native pipelined I/O; wasm32 sequential chunks — one API, no mmap / no alternate scan modes).
- Keep the **positional** CLI contract (`<creature.json> <data_dir>`) stable.
- **GPU plumbing (Issue #80, #83, #180):** `--gpu <auto|on|off>` (and `NEAT_SCORER_GPU=…`, CLI wins) selects between the CPU pipeline (emits `gpuBackend: "cpu-fallback"`) and `wgpu` adapter detection. **`auto` is the default since #83** (multi-creature directory path only; single-creature stays CPU): it falls back silently to CPU when no GPU is found, when the cost is non-MSE, or when a creature exceeds the GPU shader cap. `off` skips `wgpu` entirely; `on` exits non-zero if a GPU cannot host the run. The `forward_mse_batched` shader caps at **256 neurons** per creature (`MAX_NEURONS_PER_CREATURE`, fixed `private` activation array); creatures above it route to the **`forward_mse_scratch`** kernel (#182), which holds activations in a runtime-sized `storage` buffer bounded by a memory budget + grid-stride loop — so large creatures (observed 4139 neurons) now run on the GPU. Directory-mode `auto` still runs a CPU-only pre-flight (`multi_score::gpu_directory_compatible`, #180) **before** creating any GPU device — an unhostable set (unsupported squash, shape mismatch, or absurd neuron count) never spins up a `wgpu` context, guaranteeing a clean CPU fallback (valid JSON, exit 0). Since **#305** both kernels' `activate()` inline every **point-wise** squash (`SquashType` 0..=31), and since **#312** they also reduce the three **aggregate** squashes MINIMUM/MAXIMUM/IF (32..=34) inline (min / max / synapse-type branch, matching `neat_core::batch_scoring::neuron_activation_scalar`) and host **constant neurons** (clamped bias, synapses ignored, flagged by `NeuronGpu.is_constant`) — so the real GRQ-cluster creature (aggregates + 3 constant neurons) is now GPU-hostable. `SynapseGpu` carries a `synapse_type` field for IF's condition/positive/negative buckets. Only the remaining three aggregates HYPOT/HYPOTv2/MEAN (35..=37) stay "unsupported" and force the fallback via `squash_supported`. The new `gpuBackend` JSON field never replaces or shifts the existing keys — `trainingReadBackend` and the rest stay as-is.
- **Cost selector (Issues #120, #121, #134):** `--cost <NAME>` picks the loss function. Accepts the seven TypeScript `BUILT_IN_COST_NAMES` values (`MSE` (default), `MAE`, `MAPE`, `MSLE`, `HINGE`, `CROSS_ENTROPY`, `CATEGORICAL_ERROR`); unknown values hard-error via clap. No env-var override. All seven now dispatch through `accumulate_cost_sum` — Issue #134 unblocked `CATEGORICAL_ERROR` after `categorical_error_sum_batch_packed` landed via `NEAT-AI-core#88`. The GPU `forward_mse_batched` kernel is MSE-only — non-MSE costs run on the CPU pipeline under `--gpu auto` and hard-error under `--gpu on`. The resolved name is echoed back as the `costName` JSON field. See the README "Cost function selector" section for per-cost examples.
